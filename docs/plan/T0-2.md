# T0-2 仕様書 docs/spec.md

- モデル: opus
- 依存: T0-1
- 作成ファイル: `docs/spec.md` のみ（コードは書かない）

## 目的

テストを書くエージェントと実装するエージェントが共通で参照する、唯一の仕様を作る。
`docs/plan/README.md` §4 の契約を正とし、それを詳細化する。矛盾を見つけたら spec 側で解消し、報告に書く。

## 章立て（節番号を固定する。各カードはこの番号で参照する）

1. 用語（session name、chat_id、binding、許可ユーザー、agent トークン）
2. protocol メッセージ: 各バリアントの JSON 例、version 不一致時の挙動
3. agent MCP 面: initialize / tools/list / tools/call / ping / 通知 3 種の入出力 JSON 例。エラーコード
4. agent の WS 挙動: 接続ヘッダ、Hello、Welcome 待ち、再接続 backoff（1s から倍々、上限 30s）、Error 受信時
5. relay の Slack 受信
   - 5.1 署名検証（公式の計算方法、時刻窓）
   - 5.2 Events API envelope 例（`url_verification`、`event_callback` の message スレッド返信、bot 投稿、`message_changed`）。
     判定規則: `event.type == "message"`、`subtype` なし、`bot_id` なし、`thread_ts` あり、`thread_ts != ts`
   - 5.3 event_id による重複排除（直近 1000 件）
   - 5.4 slash command の form 例と、応答 body（`response_type: ephemeral`、`static_select` の blocks 例、`action_id: sccr_select`）
   - 5.5 interactions の `block_actions` payload 例（`actions[0].selected_option.value`、`channel.id`、`user.id`、`response_url`）
6. relay のルーティング規則
   - 6.1 選択: root 投稿 `Connected to session *{name}*. Reply in this thread.` の ts を thread_ts として binding 保存
   - 6.2 スレッド返信: 許可ユーザー判定、binding 検索、権限返答判定（§7）、Inbound 送信、offline 時の返信文
   - 6.3 agent の Reply: chat_id 分解、chunk（3900 文字）、スレッド投稿
   - 6.4 `/cc list`、`/cc unbind`（そのスレッド内では使えないため、チャンネル内の自分の binding を全削除）、`/cc help`
   - 6.5 bot 未招待で投稿失敗したとき、`response_url` に ephemeral で `Invite the bot to this channel first.`
7. 権限中継: pending 表（request_id → chat_id, session, 作成時刻、30 分で失効）、プロンプト文、`parse_verdict` 規則
   （`^\s*(y|yes|n|no)\s+([a-km-z]{5})\s*$`、大文字小文字無視、regex クレートを使わず手書き）
8. agent WS 認証: Bearer → SHA-256 → 状態ファイル照合。`SCCR_DEV=1` 時は `dev` も受理。最初のフレームが Hello でない、
   version 不一致、同名接続中 → `Error` を送って切断
9. OIDC: authorize URL（`https://slack.com/openid/connect/authorize`、`scope=openid profile`、`response_type=code`、state、nonce、redirect_uri）、
   token 交換（`POST https://slack.com/api/openid.connect.token`、form: code, client_id, client_secret, redirect_uri）、
   id_token claims 例と検証項目、pending state 10 分失効、Cookie 名 `sccr_sid`（24 時間）
10. 管理画面: `/` の表示項目、`POST /tokens`（form `label`）、発行直後だけ平文表示
11. 状態ファイル形式（README §4.5）
12. 開発モード `SCCR_DEV=1`: `/dev/inject` の body `{"session","chat_id","user","text"}`、Slack 投稿を stdout に出す `LogSlack`
13. Slack 表示文言一覧（offline、未許可は無応答、help 文、エラー文）
14. 意図的にテストしないもの
