- モデル: sonnet
- 依存: T0-2
- 参照: spec §5.1、README §4.6
- 変更ファイル: `crates/relay/Cargo.toml`（hmac、sha2、hex、subtle）、`crates/relay/src/lib.rs`（`pub mod slack;`）、`crates/relay/src/slack/mod.rs`、`crates/relay/src/slack/verify.rs`、`crates/relay/src/slack/verify/tests.rs`

必須テスト対象（認証境界）。

## 公開 API

```rust
#[derive(Debug, PartialEq)]
pub enum VerifyError { BadTimestamp, Stale, BadSignature }
pub fn verify(secret: &str, timestamp: &str, body: &[u8], signature: &str, now_unix: i64) -> Result<(), VerifyError>;
pub fn sign(secret: &str, timestamp: &str, body: &[u8]) -> String; // "v0=..." (tests and e2e use it)
```

## テスト（先に書く）

- `valid_signature_ok`: `sign` の出力で検証が通る
- `known_vector`: 固定の secret、timestamp、body に対する期待 hex を、テスト内で `hmac` を直接使って計算した値と一致させる
- `tampered_body_fails`
- `wrong_secret_fails`
- `old_timestamp_fails`: now - 301
- `future_timestamp_fails`: now + 301
- `boundary_300_ok`
- `non_numeric_timestamp_fails`: `BadTimestamp`
- `missing_v0_prefix_fails`
- `non_hex_signature_fails`

## 実装

- 比較は `subtle::ConstantTimeEq`
- relay は bin クレートなので `src/lib.rs` を作り、`main.rs` からは `sccr_relay::...` を使う
