# T2-2 agent の stdio ループ

- モデル: sonnet
- 依存: T2-1
- 参照: spec §3、§4
- 変更ファイル: `crates/agent/Cargo.toml`（tokio）、`crates/agent/src/main.rs`、`crates/agent/src/stdio.rs`、`crates/agent/tests/stdio.rs`

## 公開 API

```rust
// stdio.rs
pub async fn run<R, W>(
    input: R,                                        // AsyncBufRead
    output: W,                                       // AsyncWrite
    to_relay: tokio::sync::mpsc::Sender<protocol::AgentMsg>,
    mut to_stdout: tokio::sync::mpsc::Receiver<serde_json::Value>,
) -> std::io::Result<()>;
```

- input の各行を `mcp::dispatch` に渡す。`Respond` は output に書く。`Emit` は `to_relay` へ送る
- `to_stdout` から来た Value も output に書く（WS 側から来た通知用）
- 1 行ごとに flush する。input が EOF になったら Ok で返る

## テスト（先に書く、`tests/stdio.rs`）

lib を持たない bin クレートなので、テストはバイナリを `std::process::Command` で起動して行う。

- `initialize_over_stdio`: `CARGO_BIN_EXE_sccr-agent` を起動し、initialize 1 行を書くと 1 行の JSON 応答が返る
- `exits_on_eof`: stdin を閉じるとプロセスが終了コード 0 で終わる
- `stdout_has_only_json`: 応答行がすべて JSON としてパースできる

## 実装

- `main.rs`: tokio ランタイム、stdio::run を起動。`SCCR_RELAY_URL` と `SCCR_TOKEN` が無い場合は WS を起動しない（T3-1 で追加）
- ログは `eprintln!` で十分（tracing は入れない）
