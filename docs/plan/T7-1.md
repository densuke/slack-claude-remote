# T7-1 デプロイ資材

- モデル: sonnet
- 依存: T6-3
- 前提: ホスト名はプレースホルダ `slcc.fuga.jp`。実値は人が差し替える
- 変更ファイル: `deploy/*`、`README.md`

## 作成物

- `deploy/Caddyfile.snippet`
  ```
  slcc.fuga.jp {
      reverse_proxy 127.0.0.1:9996
  }
  ```
- `deploy/sccr-relay.service`: `User=sccr`、`EnvironmentFile=/etc/sccr/env`、`WorkingDirectory=/var/lib/sccr`、
  `ExecStart=/usr/local/bin/sccr-relay`、`Restart=always`、`NoNewPrivileges=true`、`ProtectSystem=strict`、`ReadWritePaths=/var/lib/sccr`
- `deploy/env.example`: README §4.4 の relay 変数すべて。値は空または例
- `deploy/slack-manifest.json`:
  - bot scopes: `commands`、`chat:write`、`channels:history`、`groups:history`
  - user scopes: `openid`、`profile`
  - slash command `/cc` → `https://slcc.fuga.jp/slack/commands`
  - event subscriptions `message.channels`、`message.groups` → `https://slcc.fuga.jp/slack/events`
  - interactivity → `https://slcc.fuga.jp/slack/interactions`
  - redirect URL → `https://slcc.fuga.jp/auth/callback`
  - `socket_mode_enabled: false`
- `README.md`:
  - 概要と構成図
  - e2 側: ビルド（e2 でビルド、または Mac で `x86_64-unknown-linux-musl` クロスビルド）、ユーザー作成、配置、systemd、Caddy 追記
  - Slack 側: manifest からアプリ作成、インストール、秘密の取得、bot をチャンネルに招待
  - 初回ログイン: `https://slcc.fuga.jp/` → トークン発行
  - Mac 側: `claude mcp add sccr -e SCCR_RELAY_URL=... -e SCCR_TOKEN=... -- /path/to/sccr-agent`、
    `claude --dangerously-load-development-channels server:sccr`、`SCCR_SESSION_NAME`
  - 使い方: `/cc`、`/cc list`、`/cc unbind`、`yes xxxxx` / `no xxxxx`
  - 既知の制限: channels は research preview、Claude 終了でセッション消滅、relay 再起動でログアウト
  - 意図的にテストしていないもの
